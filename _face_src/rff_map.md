# 边境 / 海洋 头像取材记录

## 一、边境（RFF，Wii）——已接入 31 人

### 源

- 路径：`G:/BaiduNetdiskDownload/边境图片导出/`（305 MB，5819 张 PNG + 4 张 PSD）
- 来源：贴吧 lwyx2014《【资源重发】符文工房边境和海洋图片导出》——
  改进 EveryFileExplorer 后从游戏 rom 批量导出，按导出批次编号建子目录（`00001`、`00915`…）。
- 命名：`FACE<编号>_<表情>_<帧>.png`，例如 `FACE01_N_0.png`。
  表情代号见过 `N`（通常）、`S0`/`S1`（笑/特殊）、`W`、`L`、`N_S`；带 `_R` 后缀的是同图左右翻转。

### 命名的由来

边境的对话立绘是 **480 高、宽度不等** 的半身像（宽 296–568），一人一套多表情：

| FACE 编号 | 表情张数 | 判定 |
|---|---|---|
| 00 | 5 | 主角 ラグナ |
| 01–11 | 9–18 | 花嫁候补（台词多，表情最全） |
| 12 / 13 | 9 / 9 | エリス 白 / 黑（同构图换色，见下） |
| 14–31 | 2–5 | 居民（台词少） |

`FACE12_N_0` 与 `FACE13_N_0` 的 alpha 包围盒完全相同（116,116,404,480）但 md5 不同，
是同一张画换色 —— 对应名册里「艾莉丝（白／黑）双子」一条。

早期的推断思路是 **FACE = 站内名册序号 + 1**（名册序号含主角，即 `FACE00` 是第 0 条），
用角色描述反查锚点。这个思路在花嫁段（FACE01–13）和居民前段（14–23）成立，
但**从 FACE24 起失效**（见下一节修订），下面的锚点表保留作历史记录，其中「つぶて」一条是错的：

| 锚点 | 名册描述 | 当时判定 | 实际情况 |
|---|---|---|---|
| ラピス | 教会的修女兼护士 | FACE03 | ✅ 对，深蓝长发＋白色修女头巾 |
| ステラ | CV 斉藤貴美子 | FACE19 | ✅ 对，紫红头巾的老妇 |
| ミネルバ | CV 鹿野潤 | FACE24 | ❌ 错，FACE24 是砾（小妖精），米涅鲁巴在 FACE25 |
| つぶて | 自称武蔵大和守 | FACE28 | ❌ 错，FACE28 是罗兰德（白须＋黑猫的老者），砾在 FACE24 |

教训：靠「角色文字描述 + 名册顺序」推编号，只要名册顺序有一处不同就会整段错位；
这类无名资源必须拿官方立绘逐张对印才可靠。

另外 `ラピス = Lara`（名册 `e` 字段）与 fandom 的「Lara the nurse」一致，可作英文名侧旁证。

### 重建

```bash
python _build_rff_faces.py     # 读 _face_src/rff/FACE##.png → assets/face/rff/<slug>.png
```

裁切参数：方框边长 = alpha 高度 × 0.78，顶边再上移 1.5% 画面高，水平按 alpha 居中，输出 160×160。
`HEAD_RATIO` 偏大时头发会被切、偏小时留白多，按需微调。
